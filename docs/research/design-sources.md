- **Component types:**

  - Hooks: Copilot [`.github/hooks/impeccable.json`](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/.github/hooks/impeccable.json) (`postToolUse` on `edit|create|apply_patch`); Claude [`plugin/hooks/hooks.json`](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/plugin/hooks/hooks.json) (`SessionStart`, `PostToolUse`, `Stop`); Codex `.codex/hooks.json`; Cursor `.cursor/hooks.json`; Grok `.grok/hooks/`.   - Engine/CLI: Rust engine (`crates/`, `Cargo.toml`) released as platform binaries; launcher script [`scripts/impeccable`](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/.github/skills/impeccable/scripts/impeccable) (+ `.cmd`); npm CLI `impeccable` (`bin: cli/bin/cli.js`, `engines.node >=18.19.0`, [IMP package.json](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/package.json)).

- **Install** ([IMP README L94-L162](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/README.md#L94-L162)): `npx impeccable install` (detects tools, project/global, offers hook); Claude `/plugin marketplace add pbakaus/impeccable` ([marketplace.json](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/.claude-plugin/marketplace.json), source `./plugin`); Grok plugin; git submodule + `npx impeccable link` (skills only, no hooks, L122-L125); manual copy of a dot-folder (Copilot → `.github/`, L140).

The extension "has no extension runtime, activation events, telemetry code … or automatic detector hooks" and warns against duplicate skill copies ([IMP vscode/README.md](https://github.com/pbakaus/impeccable/blob/035c8f319edd019936525a062fe99e83ca8d12c6/vscode/README.md)).
- **Versioning:** 102 tags in families `skill-v*`, `cli-v*`, `engine-v*`, `loop-v*` ([tags](https://github.com/pbakaus/impeccable/tags)); latest Releases `skill-v4.8.2`, `cli-v4.8.2`, `engine-v0.1.22` (Latest), pre-release `loop-v0.1.0` ([releases](https://github.com/pbakaus/impeccable/releases)). Network: fetches visual directions from the `impeccable.style` catalog when a new design starts, even with telemetry off (L211). Image-based "build path" only when the harness can generate images (L205).
- **Executable hooks:** yes, see above; README warns "Hooks run outside model approval … the first edit can download the engine" (L207). Live mode "Apply" can run `codex`/`claude` CLI with approvals and sandboxing off (L72).
- **Cross-references:** one skill routing to its own `reference/*.md` playbooks and to its 4 agents; agents expect paths into `reference/` (e.g. `reference/document.md`). Hallmark's README credits Impeccable as inspiration ([HM README L108](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/README.md#L108)).

## Overlap

All four plus taste-skill target the same problem ("anti-AI-slop" frontend design). Shapes differ:

| | Scope | Enforcement | Generated assets |
|---|---|---|---|
| anti-slop | UI + copy + a11y + responsive + code comments; "a filter, not a style guide" | Prompt rules + Delivery Gate report; Python contrast checker | none |
| impeccable | Full design workflow, 24 commands (shape, critique, audit, polish, live, document DESIGN.md …) | Rust detector (62 rules), hooks on edit/stop, browser extension | optional comps via host image gen |
| hallmark | New pages/landing sites; dealt themes; "never on an existing design unless named" | Node `sloplint` (static + puppeteer render), optional Claude hook | photos library; optional Together AI images |
| taste-skill | Frontend build + checks (`design-taste-frontend`) | Node gate script via skill `Stop` hook; Node 22 + Chrome | n/a (image skills moved out) |
| imagegen-skills | Images first (comps, mobile, brand kits) → code | none (prompt only) | host image gen required |

- **Mutual exclusivity:** anti-slop, impeccable, hallmark and taste-skill would each try to own the same "design a page" request; impeccable's VS Code README already warns duplicate skill copies make selection ambiguous. Installing more than one model-invoked design skill is likely to cause routing conflicts; hallmark narrows itself to new builds, impeccable claims nearly every frontend task.
- **Overlapping artefacts:** impeccable and anti-slop both expect a project `DESIGN.md` (impeccable also `PRODUCT.md`, `.impeccable/`); hallmark reads `DESIGN.md`/`design.md` and writes `.hallmark/`. Three different state folders and a shared `DESIGN.md` name with different expected contents.
- **Executable surface:** impeccable (hooks + downloaded binary + network catalog), taste-skill (Stop hook, Node gate), hallmark (Node scripts, optional hook, optional API key) vs anti-slop (Python checker only) and imagegen-skills (none).
- **Copilot fit:** impeccable is the only one shipping Copilot-native files (`.github/skills|agents|hooks`) and a VS Code extension; anti-slop's installer targets Copilot via `.agents/skills` + `AGENTS.md` pointer; hallmark only via `npx skills`; imagegen-skills and taste-skill not at all.
- **imagegen-skills `image-to-code` vs proposed `/replicate-ui`:** little direct overlap. `image-to-code` *generates* its own design images first and treats them as "the primary visual source of truth", then extracts text, typography, spacing, colour and components and codes the site; it is mandated image-first, Codex-oriented, and makes no mention of user-supplied screenshots, Figma or prototypes, design tokens, or producing an implementation plan ([IG image-to-code SKILL.md L45-L60](https://github.com/Leonxlnx/imagegen-skills/blob/beb16b0d0f4dae9a6f5cb04ea41e97b93a54ab8e/skills/image-to-code/SKILL.md#L45-L60), [§21-25 extraction rules](https://github.com/Leonxlnx/imagegen-skills/blob/beb16b0d0f4dae9a6f5cb04ea41e97b93a54ab8e/skills/image-to-code/SKILL.md#L721-L835)). Its extraction sections (text, typography, spacing, button/component, colour) could be reused as a checklist for `/replicate-ui`'s analysis step; its generation mandate would conflict. Impeccable's `extract`/`document` commands (DESIGN.md, tokens) are a closer match for the token-mapping half.
