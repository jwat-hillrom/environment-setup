# Agent orchestration (VS Code Copilot harness vs GitHub Copilot CLI)

Research for issue #11. Researched 2026-11-11 against primary sources only (code.visualstudio.com, the microsoft/vscode-docs source of those pages, docs.github.com). Builds on [host-discovery.md](https://github.com/jwat-hillrom/environment-setup/blob/research/host-discovery/docs/research/host-discovery.md) (file locations and frontmatter discovery are not repeated here). Every claim links its source. "Copilot harness" = the default VS Code agent runtime; "Local harness" = the deprecated VS Code runtime (removed by Feb 2027).

## Summary answer

- **Orchestration = subagents.** On both hosts the main agent delegates to a subagent that runs in its **own context window** and returns only its result. The Copilot harness in VS Code and Copilot CLI use the **same native `task` tool**; the Local harness uses `runSubagent` (not portable) ([VS Code subagents](https://code.visualstudio.com/docs/agents/run/subagents#_subagents-by-harness), [CLI tool list](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#agent-and-task-delegation-tools)).
- **A subagent can be a specific custom agent** on both hosts — ask for it by name in the prompt/instructions ("Use the X agent to…"), or let the main agent infer it from the agent's `description` ([CLI custom agents](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli#using-a-custom-agent)). VS Code recommends harness-neutral wording ("delegate this review to the reviewer agent") over naming a tool ([migration FAQ](https://code.visualstudio.com/docs/agent-customization/migrate-customizations#_why-does-my-coordinators-subagent-invocation-stop-working)).
- **Restricting which workers a coordinator may call (`agents`) and `handoffs` are Local-harness only**; the Copilot harness rejects both ([custom agent file reference](https://code.visualstudio.com/docs/agents/reference/custom-agent-file-reference#_harness-compatibility)). On the Copilot harness/CLI, the controls are per-worker: `disable-model-invocation`, `user-invocable`, `tools` (`agent` alias), `model`.
- **Different models per step: yes.** A worker's `model` (string or ordered list) applies when it runs as a subagent; CLI adds `model-policy: required` and a `/subagents` per-agent override ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#custom-agent-frontmatter-fields)).
- **Parallel & nesting:** CLI documents concurrency (plan-based, up to 32) and depth limits, `/fleet` for parallel orchestration, `/tasks` to monitor, and `list_agents`/`write_agent` for messaging running agents. VS Code Copilot harness says only "parallel when the harness supports it"; Local harness nesting is opt-in, max depth 5.
- **Skills:** model-/user-invocation controls exist on both hosts; `context: fork` (run skill in a subagent) is VS Code-only and experimental. Skill-calls-skill is not explicitly documented on either host.
- **CLI-only:** `/fleet`/`--fleet`, `/delegate` (`&` prefix) to Copilot cloud agent, `--resume`/`--continue`, `/fork`, sidekick agents, `copilot workflow run` (extension-provided dynamic workflows).
- **State between steps/sessions:** files in the repo (the only fully deterministic, host-neutral option); Copilot Memory (cloud, shared by VS Code Copilot harness + CLI, but model-curated and not guaranteed to be applied); VS Code Local-harness memory files (deprecated); subagents in CLI can read but not write memory.

## Subagents

**Invocation.** Copilot harness: "Request a subagent in your prompt, or let the main agent decide when to delegate… Copilot uses the native `task` tool for delegation, rather than Local's `runSubagent`… Do not assume the tools accept identical arguments" ([VS Code subagents](https://code.visualstudio.com/docs/agents/run/subagents#_subagents-by-harness)). `agent/runSubagent` "isn't a portable delegation tool name" ([file ref: tools](https://code.visualstudio.com/docs/agents/reference/custom-agent-file-reference#_tools)). CLI exposes `task` ("Run subagents"), `list_agents`, `read_agent` ("Check background agent status"), `write_agent` ("Send a message to a running agent") ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#agent-and-task-delegation-tools)). The tool alias `agent` (compatible: `custom-agent`, `Task`) "Allows a different custom agent to be invoked" ([config ref](https://docs.github.com/en/copilot/reference/custom-agents-configuration#tool-aliases)).

- **From an agent:** instructions in the agent body, e.g. "Use the local-coder agent to …" ([CLI how-to](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli#delegating-focused-tasks-to-a-specific-model)).
- **From a skill:** no host documents a skill-specific delegation mechanism other than `context: fork` (VS Code). Because skill content is "injected into the conversation" ([CLI skills ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#skills-reference)), a skill body that says "delegate X to the Y agent" is an instruction to the main agent, which then uses `task` — inferred, not stated.
- **Local harness** additionally lets a prompt file include the `agent` tool set ([vscode-docs source](https://raw.githubusercontent.com/microsoft/vscode-docs/main/docs/agents/run/subagents.md)).

**Context isolation / what the subagent sees.** "Each subagent works in its own context. The harness determines which instructions and conversation history it receives" ([VS Code concepts](https://code.visualstudio.com/docs/agents/concepts/agents#_subagents)). CLI: a custom agent spawned as a subagent does **not** receive repository instruction files (`copilot-instructions.md`, `AGENTS.md`, `CLAUDE.md`) unless it sets `include-custom-instructions: true`; `general-purpose` receives them; `explore`, `task`, `code-review` do not; `--no-custom-instructions` overrides everything ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#repository-custom-instructions-for-subagents)). VS Code does **not forward** `include-custom-instructions` when converting agents for the Copilot runtime ([file ref](https://code.visualstudio.com/docs/agents/reference/custom-agent-file-reference#_copilot-specific-configuration)). Local harness: subagent gets the delegated task and applicable instructions, not the main history; inherits main agent's instructions and tools unless a custom agent is specified; each invocation is **stateless** (no follow-up messages); ask-questions and todo tools unavailable ([vscode-docs source](https://raw.githubusercontent.com/microsoft/vscode-docs/main/docs/agents/run/subagents.md)).

**What is returned.** "Returns a focused result to the main agent… the main agent uses the subagent's result without adding all of its intermediate work to the main context" ([VS Code concepts](https://code.visualstudio.com/docs/agents/concepts/agents#_subagents)). CLI built-ins shape output: `explore` "Returns focused answers under 300 words"; `task` "Returns brief summary on success, full output on failure" ([CLI built-in agents](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#built-in-agents)). In VS Code the Agents window shows subagents as read-only chats ([VS Code subagents](https://code.visualstudio.com/docs/agents/run/subagents#_agents-window)); in CLI `/tasks` lets you view details, kill, promote to background, or "teleport" into a subagent and send steering messages ([CLI tasks dialog](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#tasks-dialog-shortcuts)).

**Built-in CLI subagents:** `code-review`, `explore` ("Safe to run in parallel"), `general-purpose`, `research`, `rubber-duck`, `security-review`, `task` ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#built-in-agents)).

**Parallelism and limits.**

- CLI: depth = nesting levels; concurrency = simultaneous subagents across the session tree; requests over the limit are rejected until one completes. Defaults: depth 6 (max 256); concurrency by plan — Free/Education 2, Pro/Pro+ 4, Max 8, Business 16, Enterprise/usage-based 32. Overrides `subagents.maxConcurrency`/`subagents.maxDepth` only for usage-based billing ([CLI subagent limits](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#subagent-limits)). Env vars `COPILOT_SUBAGENT_MAX_CONCURRENT` (default 32) and `COPILOT_SUBAGENT_MAX_DEPTH` (default **4**) are also documented ([CLI env vars](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#environment-variables)) — see Open uncertainties.
- VS Code Copilot harness: no numeric limits published; "independent subtasks can run in parallel when the harness supports concurrent subagents" ([VS Code concepts](https://code.visualstudio.com/docs/agents/concepts/agents#_subagents)).
- VS Code Local: nested subagents off by default; `chat.subagents.allowInvocationsFromSubagents` enables; "Nesting is limited to a maximum depth of five" ([vscode-docs source](https://raw.githubusercontent.com/microsoft/vscode-docs/main/docs/agents/run/subagents.md)).
- Cost: each subagent makes its own model requests ([VS Code concepts](https://code.visualstudio.com/docs/agents/concepts/agents#_subagents), [CLI delegation concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/choosing-and-delegating-agent-work/delegating-and-parallelizing-work-with-agents#considerations-when-using-the-fleet-command)).

On the Copilot harness the replacement for a handoff is a **session handoff**, which "carries the full conversation history and context" and can change harness, environment, or agent role; "Cloud sessions don't receive local-session handoffs" ([VS Code sessions](https://code.visualstudio.com/docs/agents/concepts/sessions#_hand-off-a-session)). The CLI equivalent of switching role is `/agent` or `--agent` (session agent), distinct from delegating to a subagent ([CLI custom agents concept](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents#custom-agents-and-subagents)). CLI agent ID = file name (subdirs joined with `--`); `name` doesn't dedupe ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#custom-agent-locations)). Local agent names in `agents` are case-sensitive ([file ref](https://code.visualstudio.com/docs/agents/reference/custom-agent-file-reference#_subagent-configuration)).

Built-in CLI guard: `code-review`/`security-review` never forward a full review to another review agent ([CLI built-ins](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#built-in-agents)).

## Skills invoking skills

- Invocation modes (both hosts): default = user `/name` + model-selected; `user-invocable: false` = model only; `disable-model-invocation: true` = user only; both = disabled ([Agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills#_use-skills-as-slash-commands), [CLI skills ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#skill-frontmatter-fields)).
- CLI has a `skill` tool ("Invoke custom skills") ([CLI tools](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#other-tools)); VS Code has a skill tool behind `github.copilot.chat.skillTool.enabled` ([Agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills#_run-a-skill-in-a-forked-context)). Neither host documents that one skill can programmatically call another; a skill naming another skill is an instruction the model may follow via the skill tool (inference).
- CLI skill names may contain colons (namespacing, e.g. `my-plugin:search`) ([CLI skills ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#skill-frontmatter-fields)); VS Code silently skips names with colons/slashes; plugin prefix is added automatically (`/my-plugin:test-runner`) ([Agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills#_header-required)). Same-named skills from two CLI plugins coexist as `/plugin-a/search`, `/plugin-b/search` ([CLI skill locations](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#skill-locations)).
- **`context: fork`** (VS Code, experimental): the skill "executes in a dedicated subagent and only its final result is returned to the parent agent"; requires `github.copilot.chat.skillTool.enabled` ([Agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills#_run-a-skill-in-a-forked-context)). Not listed among CLI skill fields.
- Prompt-file conversion adds `disable-model-invocation: true` and drops prompt `agent`/`model`/`tools`; "A skill's instructions do not replace a tool allow-list" ([migration](https://code.visualstudio.com/docs/agent-customization/migrate-customizations#_convert-prompt-files-to-skills)). Implication: a skill cannot by itself pin a model or tool set; pair it with a custom agent.

## Per-agent `model` and `tools`

- **VS Code Copilot harness:** `model` string or array in preference order ("using the first available"); if omitted, current model. `model-policy` recognized but **not forwarded** on conversion. `reasoning-effort` supported ([file ref](https://code.visualstudio.com/docs/agents/reference/custom-agent-file-reference#_header-fields)).
- **CLI:** `model` (unset → inherits outer agent's model); `models` (priority list, overrides `model`); `modelPolicy` `preferred`/`required`; `reasoningEffort`. Precedence: explicit per-call value → `subagents` override in `~/.copilot/settings.json` (or `/subagents` picker) → agent definition → parent session. Unhonorable model falls back to session model unless `required`, in which case dispatch is refused. "When the session model is set to `Auto`… subagents always inherit the resolved session model regardless of this field" ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#custom-agent-frontmatter-fields)). `--model` beats agent `model` unless `model-policy: required` ([CLI options](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#command-line-options)). Documented use case: route bounded tasks to a local BYOK model while the main session uses a cloud model ([CLI how-to](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli#delegating-focused-tasks-to-a-specific-model)).
- **Local:** model order = explicit `runSubagent` model param → agent `model` → Auto (`chat.subagents.defaultToAuto`) → main model; selections above the main model's cost tier are refused ([vscode-docs source](https://raw.githubusercontent.com/microsoft/vscode-docs/main/docs/agents/run/subagents.md)).
- **Tools:** Copilot aliases `execute`, `read`, `edit`, `search`, `agent`, `web`, `todo`, `*`; `<server>/*` for MCP ([file ref](https://code.visualstudio.com/docs/agents/reference/custom-agent-file-reference#_tools)). CLI default `["*"]`; `*` anywhere grants all; `strict-tools-list: true` omits default tools ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#custom-agent-frontmatter-fields), [CLI how-to](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli#delegating-focused-tasks-to-a-specific-model)); VS Code does not forward `strict-tools-list`. Unrecognized tool names are ignored ([config ref](https://docs.github.com/en/copilot/reference/custom-agents-configuration#tools)). CLI plan mode restrictions are inherited by delegated helpers ([CLI security](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#plan-mode)).

## CLI-specific orchestration features

- **`/fleet [PROMPT]` / `--fleet`:** main agent splits the task, acts as orchestrator managing dependencies, runs subagents in parallel where possible; each subagent has its own context window. Name a custom agent in the prompt (`@AGENT-NAME`) or let Copilot choose. `--fleet` works with `-i`, `-p`, or piped stdin; not with `--acp`. Plan mode offers "Accept plan and continue in Autopilot execution mode + /fleet" ([fleet how-to](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/speed-up-task-completion), [delegation concepts](https://docs.github.com/en/copilot/concepts/agent-capabilities/choosing-and-delegating-agent-work/delegating-and-parallelizing-work-with-agents)).
- **`/delegate [PROMPT]` or `&` prefix:** pushes to Copilot cloud agent; asks to commit unstaged changes to a new branch; opens a draft PR targeting current branch (`--base` to change) ([delegate how-to](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/delegate-tasks-to-cca)). Cloud agent custom-agent versions are pinned by commit SHA of the profile ([config ref](https://docs.github.com/en/copilot/reference/custom-agents-configuration#versioning)).
- **Autopilot:** `--autopilot`/`/autopilot` continues until `task_complete`; `--plan --mode autopilot` = plan-then-autopilot; `--max-autopilot-continues` ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#command-line-options)).
- **Sessions:** `-r/--resume[=ID|name]`, `--continue`, `--session-id`, `/resume`, `/fork` (works while agent runs; `/fork worktree`), `/new worktree`, `-w/--worktree`, `/restart` restores all live sessions; `-p` exit summary prints a `copilot --resume=SESSION-ID` hint; `-p` waits up to `COPILOT_TASK_WAIT_TIMEOUT_SECONDS` (600) for background agents ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference)).
- **Other:** `/rubber-duck`, `/review`, `/security-review`, `/research` invoke built-in specialists; `/after`, `/every` schedule prompts (experimental); `copilot workflow run NAME` runs an extension-provided dynamic workflow non-interactively (cannot combine with `--fleet`, `--agent`, `--resume`) ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#using-copilot-workflow-run)); sidekick agents fire on `user.message` / `session.context_changed` ([CLI sidekick](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#sidekick-agents)).

## Persisting state between steps and sessions

- **Repository files:** host-neutral; Copilot Memory docs recommend custom instructions for rules that must apply, since "Neither memories nor custom instructions guarantee that Copilot will follow a rule every time" ([Copilot Memory](https://docs.github.com/en/copilot/concepts/agents/copilot-memory#using-custom-instructions-alongside-copilot-memory)). Nested sessions share the parent's folder/worktree but not conversation ([VS Code sessions](https://code.visualstudio.com/docs/agents/concepts/sessions#_chats-within-a-session)).
- **Copilot Memory (cloud):** repository facts + user preferences; shared across Copilot CLI, VS Code Copilot harness, cloud agent, code review. CLI interactive on by default; CLI `-p` off unless `--enable-memory`; VS Code via `chat.copilot.memory.enabled`. In CLI "only the root agent can use `store_memory` or `vote_memory`"; subagents read via `read_memories` ([Copilot Memory](https://docs.github.com/en/copilot/concepts/agents/copilot-memory#settings-for-each-surface), [VS Code memory](https://code.visualstudio.com/docs/agents/run/memory#_copilot-memory)). `copilot memories import FILE` bulk-imports JSONL ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#importing-memories)). Expiry: see Open uncertainties.
- **VS Code experimental repo-local memory:** `.github/copilot-memories.jsonl` with `chat.copilot.memory.local.enabled`; repository scope only; GitHub policies don't apply; can be committed ([VS Code memory](https://code.visualstudio.com/docs/agents/run/memory#_store-copilot-memory-in-the-repository-experimental)).
- **Local-harness memory files** (`/memories/`, `/memories/repo/`, `/memories/session/`; Plan agent writes `plan.md` to session memory) — deprecated with the Local harness ([VS Code memory](https://code.visualstudio.com/docs/agents/run/memory#_local-memory-files)).
- **CLI session artifacts:** `/session plan|files|checkpoints`; `/undo`/`/rewind` restores conversation and files per turn, including sub-agent edits ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#slash-commands-in-the-interactive-interface)).

## Same vs different across hosts

**Same (Copilot harness ≡ CLI):** `task` delegation tool; custom agents in `.github/agents` usable as subagents; `user-invocable`, `disable-model-invocation`, `model` (array), `tools` aliases incl. `agent`; skills with `user-invocable`/`disable-model-invocation`; Copilot Memory. VS Code states it and CLI "use the same Copilot harness and hook format" ([migration: hooks](https://code.visualstudio.com/docs/agent-customization/migrate-customizations#_migrate-hooks)).

**Different:** CLI-only — `/fleet`, `/delegate`, `/tasks`, `list_agents`/`write_agent`, sidekick agents, published concurrency/depth limits, `include-custom-instructions`/`model-policy`/`strict-tools-list` actually applied, `/subagents` model overrides, `--resume`. VS Code-only — `context: fork` skills, `skills:` agent field (documented), Agents-window subagent views, session handoff across harnesses. Local-only (deprecated) — `agents`, `handoffs`, `runSubagent`, nested-subagent setting, file memory.

## Implications for workflows

- A coordinator agent that must run on both hosts can rely only on natural-language delegation ("use the X agent to…") plus worker-side frontmatter; `agents`/`handoffs` will be rejected by the Copilot harness and are absent from CLI docs.
- Worker isolation means anything a worker needs (requirements, file paths, prior decisions) must be passed in the delegated task or written to files; CLI custom subagents additionally lack repo instructions unless `include-custom-instructions: true`, which VS Code does not forward.
- Multi-model pipelines are expressible per worker via `model`; enforcement (`model-policy: required`) is CLI-only, and CLI `Auto` session model overrides worker models.
- Parallel fan-out is bounded by plan (as low as 2 concurrent on Free in CLI); VS Code publishes no figure.
- Durable cross-session state that must be exact belongs in repository files; Copilot Memory is shared across hosts but curated, expiring, and writable only by the root agent in CLI.
- Cloud handoff (`/delegate`) produces a draft PR rather than returning a result to the caller.

## Open uncertainties

1. **CLI depth/concurrency defaults conflict** within one page: env-var table says `COPILOT_SUBAGENT_MAX_DEPTH` default 4 and `COPILOT_SUBAGENT_MAX_CONCURRENT` default 32; "Subagent limits" table says depth 6 and plan-based concurrency ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference)).
2. **Frontmatter key spelling:** CLI reference lists `modelPolicy`, `reasoningEffort`, `infer`; the CLI how-to and VS Code use `model-policy`, `reasoning-effort`, `disable-model-invocation`, and GitHub's config ref calls `infer` retired. Whether CLI accepts both spellings is not stated.
3. **Memory expiry:** VS Code says unused memories are deleted after 28 days ([VS Code memory](https://code.visualstudio.com/docs/agents/run/memory#_review-and-delete-cloud-memories)); GitHub says default 90 days, configurable 7–180 for repo facts ([Copilot Memory](https://docs.github.com/en/copilot/concepts/agents/copilot-memory#retention-and-expiry)).
4. VS Code Copilot harness: nesting depth, concurrency limits, availability of `list_agents`/`write_agent`, and whether `/fleet` exists are undocumented (CLI and VS Code share the runtime, so likely similar — inferred).
5. Whether `context: fork` works on the Copilot harness or only Local is not stated; its gating setting has a `github.copilot.chat.*` name.
6. Whether CLI honours the `skills:` agent field (not in the CLI frontmatter table).
7. No primary doc states that a skill can invoke another skill or a subagent directly; only model-mediated behaviour is implied.
8. Built-in CLI agent default models differ between "Supported models" and "Built-in agents" tables (e.g. `claude-sonnet-5.5` vs `claude-sonnet-4.6`); treat model IDs as volatile.
